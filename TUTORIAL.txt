PARTE 1 — VISÃO GERAL
================================================================================

Glam Boutique é uma loja virtual de moda feminina com painel administrativo
completo. Foi pensada para rodar em dois modos:

  - MODO DEMO (sem backend): frontend puro, dados em memória + localStorage.
    Ideal para demonstrar a UI antes de subir o banco.
  - MODO BACKEND (produção): frontend conversa com API Node/Express/MySQL,
    dados persistem de verdade.

Quando a variável VITE_API_URL existe no .env.local, o app detecta e muda
automaticamente pra modo backend (ver src/services/api.ts).

O painel administrativo (/admin) autentica contra o backend com JWT (8h).
O login de clientes (/entrar, /cadastro) é mock por enquanto.

PARTE 6 — FLUXO DE AUTENTICAÇÃO ADMIN (DETALHADO)
================================================================================

1. Usuário acessa /admin/entrar
2. Preenche email + senha
3. Frontend chama POST /api/admin/login com { email, password }
4. Backend verifica:
   a) email === process.env.ADMIN_EMAIL  (case-insensitive)
   b) bcrypt.compare(password, process.env.ADMIN_PASSWORD_HASH)
5. Se ok, backend retorna { token: "...", expiresIn: "8h" }
   Token é JWT assinado com process.env.ADMIN_JWT_SECRET
6. Frontend salva token no localStorage (zustand persist com key
   "glam-boutique-admin-auth")
7. Próximas requests admin enviam header:
      Authorization: Bearer <token>
8. Backend middleware requireAdminAuth verifica o JWT em cada rota
   protegida (salesRouter, expensesRouter, paymentMethodsRouter write,
   analytics summary).
9. Após 8h o token expira, frontend limpa state, user é redirecionado ao login.

Modos:
  - isBackendConfigured() === true → modo 'backend'
  - isBackendConfigured() === false → modo 'demo' (aceita
    admin@glamboutique.com.br + glamadmin123 hardcoded, NÃO seguro)

PARTE 7 — BANCO DE DADOS (ESQUEMA)
================================================================================

Arquivo: server/schema.sql
Banco:  glam_boutique
Engine: MySQL 8+ / InnoDB / utf8mb4

TABELAS
  1. customers
     - id, full_name, email (UNIQUE), phone, created_at, updated_at

  2. products
     - id, slug (UNIQUE), name, description, price (DECIMAL),
       category_id, brand_id, stock, images (JSON), created_at

  3. orders
     - id, order_number (UNIQUE), customer_id (FK), status,
       payment_method (pix/cartao/boleto/carteira/custom-xxx),
       subtotal, discount, shipping, total (DECIMAL), created_at

  4. order_items
     - id, order_id (FK), product_id (FK), product_name, quantity,
       unit_price (DECIMAL)

  5. expenses (saídas)
     - id, description, category, amount (DECIMAL),
       expense_date, paid (BOOLEAN), created_at

  6. payment_methods
     - id (pix/cartao/boleto/carteira/custom-*), label, enabled (BOOLEAN),
       discount_percent, max_installments, is_custom (BOOLEAN), created_at

  7. page_views (analytics real)
     - id, session_id, path, device (mobile/desktop), referrer, viewed_at

PARTE 9 — STORES ZUSTAND (ESTADO GLOBAL FRONTEND)
================================================================================

10 stores isoladas, cada uma com responsabilidade única:

  1. adminAuthStore.ts
     Login admin, token JWT, modo (backend | demo), persist em localStorage.
     É a única store que conversa com a API real via apiRequest().

  2. authStore.ts
     Mock de login/cadastro de cliente. Persist em localStorage.
     Pronto para integração futura com API de clientes.

  3. cartStore.ts
     Itens do carrinho, quantidade, cupons (GLAM10, BEMVINDA15, GLAMVIP20),
     totais, frete. Persist em localStorage.

  4. wishlistStore.ts
     IDs de produtos favoritados. Persist em localStorage.

  5. expensesStore.ts
     Lista de saídas. Persist em localStorage (mock).
     Pode ser ligado ao backend via apiRequest em expenses.js.

  6. paymentMethodsStore.ts
     Config de métodos (Pix, Cartão, Boleto, Carteiras, custom).
     Persist em localStorage (mock). Lê /api/payment-methods em produção.

  7. analyticsStore.ts
     Page views por sessionId. Persist em localStorage (mock).
     Em produção, envia para /api/analytics/pageview.

  8. toastStore.ts
     Toasts efêmeros (sucesso/erro/info). Não persist.

  9. searchHistoryStore.ts
     Últimos 8 termos pesquisados. Persist em localStorage.

  10. cookieConsentStore.ts
      Estado de consentimento de cookies (LGPD). Persist em localStorage.

PARTE 11 — CHANGELOG DE BUGS CORRIGIDOS (SESSÃO ATUAL)
================================================================================

BUG 1 — Backend não iniciava / login falhava
  Causa: server/src/index.js.bind(PORT) → só escutava em 127.0.0.1
          Outros PCs na rede não conseguiam acessar.
  Fix:   app.listen(Number(PORT), '0.0.0.0', ...)

BUG 2 — CORS bloqueava produção
  Causa: cors({ origin: 'http://localhost:5173' }) → single origin.
          Quebraria ao deployar em domínio real.
  Fix:   cors() com origin() dinâmico que aceita lista separada por
          vírgula em process.env.CORS_ORIGIN.

BUG 3 — Erro do MySQL vazava pro cliente
  Causa: catch blocks faziam res.json({ error, detail: error.message })
          Exporia schema/tabela para qualquer visitante.
  Fix:   catch agora só loga internamente com prefixo [rota.metodo]
          e retorna mensagem genérica pro cliente.

BUG 4 — ADMIN_JWT_SECRET fraco e placeholder
  Causa: 'glam-boutique-secret-key-change-in-production' no .env
  Fix:   Gerado via crypto.randomBytes(64).toString('hex')
          128 caracteres hex aleatórios.

BUG 5 — ADMIN_PASSWORD_HASH fraco/placeholder
  Causa: hash bcrypt de senha desconhecida no .env
  Fix:   Hash gerado com node scripts/hashPassword.js
          Senha inicial: glamadmin123 (trocar antes de produção real)

BUG 6 — Sem script combinado de setup do DB
  Causa: tinha db:schema e db:seed separados; usuário tinha que rodar
          manual na ordem certa.
  Fix:   Adicionado db:setup (schema + seed) e db:reset em server/package.json.

BUG 7 — Sem config de deploy no backend
  Causa: zero Dockerfile / Procfile / render.yaml / railway.json
  Fix:   server/Dockerfile + server/.dockerignore (Node 20 Alpine, healthcheck)
          nginx.conf.example recebeu bloco location /api/ com proxy_pass.

BUG 8 — Error handler genérico sem observabilidade
  Causa: console.error('Erro não tratado:', err) → stack ia pro console
          mas cliente só recebia 500 genérico, sem correlação.
  Fix:   errorId gerado (err-{timestamp base36}) + log estruturado +
          stack oculto em produção (NODE_ENV=production).

BUG 9 — .env possivelmente versionado
  Causa: risco de .env com secrets reais ir pro git.
  Fix:   Verificado: server/.env está no .gitignore, NUNCA foi commitado.
          Apenas .env.example foi commitado (template sem secrets).

BUG 10 — README desatualizado
  Causa: server/README.md falava em "próximo passo" integrar com backend,
          já estava integrado mas faltava documentar.
  Fix:   README do server reescrito com:
           - Setup local (Workbench + terminal)
           - Geração de secrets (comandos exatos)
           - Scripts npm disponíveis
           - Deploy em VPS (passo a passo Ubuntu)
           - Alternativa Docker
           - Checklist de segurança
          README raiz atualizado com seção "Deploy em produção".

PARTE 12 — DEPLOY EM PRODUÇÃO (VPS ÚNICO — RECOMENDADO)
================================================================================

CUSTO ESTIMADO: ~R$30/mês (Hetzner CX22) ou ~R$50/mês (Hostinger VPS)

REQUISITOS DO SERVIDOR
  - Ubuntu 22.04+ ou Debian 12
  - Mínimo 2GB RAM, 20GB SSD
  - IP fixo

PASSO A PASSO

1) Conectar no servidor via SSH
   $ ssh root@SEU.IP

2) Instalar Node 20
   $ curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
   $ sudo apt install -y nodejs

3) Instalar MySQL
   $ sudo apt install -y mysql-server
   $ sudo mysql_secure_installation
   $ sudo mysql -u root -p
     > CREATE DATABASE glam_boutique;
     > CREATE USER 'glam'@'localhost' IDENTIFIED BY 'SENHA-FORTE';
     > GRANT ALL PRIVILEGES ON glam_boutique.* TO 'glam'@'localhost';
     > FLUSH PRIVILEGES;
     > exit

4) Instalar Nginx + PM2
   $ sudo apt install -y nginx
   $ sudo npm install -g pm2
   $ sudo ufw allow 22,80,443
   $ sudo ufw enable

5) Clonar o projeto
   $ sudo mkdir -p /var/www && sudo chown -R $USER /var/www
   $ cd /var/www
   $ git clone https://github.com/seu-usuario/glam-boutique.git
   $ cd glam-boutique

6) Backend
   $ cd server
   $ npm ci --omit=dev
   $ cp .env.example .env
   $ # Editar .env:
   $ #   DB_USER=glam
   $ #   DB_PASSWORD=SENHA-FORTE (a mesma do MySQL)
   $ #   ADMIN_PASSWORD_HASH=<gerar novo>
   $ #   ADMIN_JWT_SECRET=<gerar novo>
   $ #   CORS_ORIGIN=https://seudominio.com.br
   $ #   NODE_ENV=production
   $ npm run db:setup
   $ pm2 start src/index.js --name glam-api
   $ pm2 startup && pm2 save

7) Frontend (build)
   $ cd ..
   $ npm ci
   $ VITE_API_URL=https://seudominio.com.br/api npm run build
   $ sudo mkdir -p /var/www/glamboutique
   $ sudo cp -r dist/* /var/www/glamboutique/

8) Nginx
   $ sudo cp nginx.conf.example /etc/nginx/sites-available/glamboutique
   $ # editar o server_name se for diferente
   $ sudo ln -s /etc/nginx/sites-available/glamboutique /etc/nginx/sites-enabled/
   $ sudo rm /etc/nginx/sites-enabled/default

9) HTTPS gratuito (Let's Encrypt)
   $ sudo apt install -y certbot python3-certbot-nginx
   $ sudo certbot --nginx -d seudominio.com.br -d www.seudominio.com.br
   # Segue as instruções, aceita redirecionar HTTP→HTTPS

10) DNS no registrador (Registro.br / Hostinger / Namecheap)
    Tipo    Nome    Valor              TTL
    A       @       SEU.IP.SERVIDOR    300
    A       www     SEU.IP.SERVIDOR    300

11) Teste
    $ curl https://seudominio.com.br/api/health
    → {"status":"ok","service":"glam-boutique-server"}

    $ curl -I https://seudominio.com.br
    → HTTP/2 200

12) Manutenção
    - Atualizar código:
        $ cd /var/www/glam-boutique
        $ git pull
        $ cd server && pm2 restart glam-api
        $ cd .. && npm ci && npm run build
        $ sudo cp -r dist/* /var/www/glamboutique/

    - Ver logs:
        $ pm2 logs glam-api         # backend
        $ sudo tail -f /var/log/nginx/access.log

    - Backup do banco (cron diário):
        $ sudo nano /etc/cron.daily/backup-mysql
        #!/bin/bash
        mysqldump -u glam -p'SENHA-FORTE' glam_boutique | gzip > /backup/glam-$(date +%F).sql.gz
        $ sudo chmod +x /etc/cron.daily/backup-mysql

  npm run db:seed      → roda seed.sql
  npm run db:setup     → schema.sql + seed.sql (ordem correta)
